# 精简工作流提示词和话术样例

让模型仅凭收到的 prompt 就能理解生成规则。工作流的样例维护文件与发给模型的样例采用相同的双字段格式。

## 自包含提示词

程序继续从工作流自己的资料文件读取内容，在组装各节点 prompt 时直接提供该阶段需要的规则与数据。采用组装时展开的做法，可复用正式字段和写作规则。把全文复制到每份模板会重复维护同一规则。

- 知识补充和条件生成目前仍要求读取旧版条件目录及模板文档。将这些指令改为实际可用的血量、容错、回合、对手与主 C 等字段说明。知识补充随附所需字段，条件生成继续随附完整的正式字段。区分当前对手和全场存活玩家，保留信息未知的情况。
- 条件生成中关于键段的说明直接引用同一 prompt 内的正式事件和字段。话术节点内联按对象选词规则，清除已展开资料中的跨文件阅读指令。保持普通生成与空组补全适用。
- 验收读取实际组装并写入溯源的 prompt，区分模型阅读指令与用户材料自身的来源定位。

## 双字段样例与拍卖预算

- 工作流样例 JSON 顶层继续按正式事件分组，用于精确匹配。组内每条只保存 `condition` 和 `utterance`。`condition` 是自然语言的事件动作及适用前提，`utterance` 是话术原句。去掉每条的重复事件字段、ID、来源、额外信息键、正式表达式和范围字段。必要的原范围以自然语言保留在条件中。
- 模型仅收到当前相关事件的样例，保留正式事件标题与双字段正文。校验工作流样例是否归入正式事件、两字段均有非空文本。独立维护工作流样例库。
- 从维护文件中移除话术原句未提及拍卖预算的现有拍卖样例。当前三轮拍卖共五条，均符合移除条件。空样例事件按原有策略和规则生成。未来新增拍卖样例须在原句中包含有据的建议预算。

## 验收

核对精简前后非拍卖样例的原句，确保必要情境仍在。检查所有发给模型的样例只有两个字段、工作流维护文件的拍卖样例已清理，以及知识补充、条件和话术节点的实际 prompt 已包含可独立使用的规则。覆盖普通生成、空组补全和空拍卖样例。
