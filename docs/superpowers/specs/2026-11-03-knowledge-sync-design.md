# 双端知识同步设计

用户已批准：本地发布与网站保存共用稳定笔记/段落 ID 的三方合并；不同段落自动合并，meta 不交给用户解决。真正正文、删改、排序分歧在管理员网页处理，只暂停冲突笔记，普通读者继续看服务器原展示版。其他笔记和代码继续同步。证据、人工保护、稳定 ID、历史均保留。

当前正文仍为 schema6。当前 meta 移出全量历史快照，历史和审计保存在 Git 跟踪的 knowledge-history 不可变记录。兼容旧格式，先部署读写兼容代码，再两端迁移；不改写 Git 历史，不删除旧证据。不变保存不得制造新版本。

共用合并输入为共同祖先、本端、远端；正文与附件成对处理。索引、校验值和 revision 重建；同文证据可合并，证据随选中的正文，未选内容留历史。身份、来源等无法自动判定的知识差异转为可读业务问题，不能整份 ours/theirs 丢弃 meta。

冲突请求和解决事件保存在 Git 跟踪的 knowledge-sync 追加记录中，不包含私有提案、账号或 raw。每篇一个未解决集合，多个新增版本并入集合，重复请求去重。解决须校验集合 revision、当前笔记 revision 和所见请求集合；新版本到达返回409且保留草稿；已解决旧请求不得复活。

网站展示版由服务器激活前持锁读取的实际运行快照确定，不假设 GitHub 就是运行版。服务器处理请求和自己的未推送保存，固定冲突笔记展示版，发布其它变化；保留候选目录、快照变化重试和健康回滚。当前运行目录不合并新代码。待部署与冲突不可再作为全局写禁令，状态跨 release 持久化和接管。

管理员网页显示共同原文/网站当前版/另一端改文，支持当前、另一端、手工合并及删除/排序选择；不显示meta JSON。编写员仍走提案，访客不能查看差异。正文/meta/历史/解决事件使用一个事务，原来源与人工修订冲突继续独立。

publish-local负责保存、合并和发布；pull-local不隐式发布，本地脏或分叉时清楚提示先publish。保留现有Actions、五分钟timer、密钥、权限、代码冲突处理。

验收包括：双端不同笔记/段落/meta-only、同段/删改/排序/第三版本、过期解决、断网重试和发布中编辑；只锁冲突笔记、固定公开版、其它变化继续；迁移幂等、历史API和恢复、所有证据保护完整；隔离双端演练后才正式迁移。
