# 万象棋模板库初始化与话术补全

先从阵容资料生成待填话术的模板库。生成工作流可以加载这份库，补全已有空组，同时从指定笔记发现和新增模板组。已有组的事件和条件由输入库决定。

## 已确认的流程

```text
阵容资料 → initialize_template → 初始库
                                      ↓
指定笔记 → template_generate → 补全已有空组 + 发现新组 → 合并校验 → 成品库及溯源
```

讨论过仅补全已有空组的做法。它便于核对组数，但会遗漏指定笔记里独立成立的新增决策。已确认采用补全和发现并行的做法，合并时以输入库的组定义为准。以下细则待设计确认。

## 初始化

- 新增项目级 `initialize_template` skill，负责识别输入格式、提取阵容清单、调用确定性生成脚本和复核结果。输入支持知识 JSON、Markdown 笔记、阵容定义表。三种输入归一为正式阵容名、英雄及品阶、天赋、装备与适用英雄的关系、适配效果牌。结构化字段、表格映射、游戏数据查询、去重和模板展开优先由代码完成。装备对象等只出现在自然语言里的关系可提取为结构化数据，并保留原文依据。遇到无法确认的名称、品阶或归属，列出待确认项，避免猜测。
- 成员英雄以明确列入阵容组成的英雄为准，包含列入组成的备选成员。单纯作为获取途径、对手或正文举例出现的对象不入组。知识 JSON 优先使用结构化阵容组成及核心英雄字段。装备只为有依据的装备与英雄组合建组。
- 每名成员英雄生成购买、选择组。2 至 3 阶英雄另生成第一次拍卖组，4 至 5 阶英雄另生成第二次拍卖组。每个天赋生成选择组。每个装备与适用英雄组合生成铸造、穿戴、转移组。每张适配效果牌生成购买、选择组。
- 每组为 `utterances: []`，`instruction` 使用用户指定文案，将阵容和实体占位替换为实际名称。购买和选择英雄要求解释定位和作用，主 C 还须说明实战能力。拍卖有资料时附建议预算。所有初始组的话术指令均禁止依赖特定局势。
- 每组表达式固定为 `我方.阵容名称 == "正式阵容名"`。正式事件的额外信息键承载英雄、天赋、装备、效果牌等身份。铸造的原装备和转移的原持有人未限定时使用 `*`。组 ID 按阵容、事件和键稳定生成。初始库作为工作流草稿，使用专门的读取校验，成品仍通过既有编审和运行校验。

## 已有库补全和新组发现

- `start` 增加 `--base-library`。运行目录保存原库快照及摘要，恢复时继续使用同一份快照。旧版有话术的组可缺省 `instruction`，空组必须提供非空 `instruction`。新创建的组写入 `instruction`，成品导入和导出保留该字段。
- 补全按空组 ID 分流。知识准备从本次指定笔记找针对该组的原文和证据，知识扩充用相关卡面和规则核实作用。事件与条件阶段读取固定定义并只产出解释角度及依据。话术阶段按锁定的条件筛选候选。用字段白名单写回话术及对应说明，逐组校对组 ID、事件、额外信息键、条件、范围和优先级。已填组保留原内容。
- 新组发现复用从笔记识别知识、扩充、推导事件和条件、生成话术的现有流程。新增组可以有自己的局面条件和解释角度。发现分支找不到独立新组时，仍可交付补全结果。
- 合并先保留原组及其顺序，再追加新组。以正式事件、额外信息键、包含范围绑定的有效条件识别同一组。比较表达式时忽略可归一化的格式差异。新组与已有组定义相同时保留已有组并记录重复来源。若同事件同键的新组有独立且更具体的条件，按现有优先级和整库匹配机制验收，验证满足细分条件时可播报，缺少细分事实时仍有适用的原组。新组不能通过覆盖已有组来解决冲突。
- 补全失败的组保留定位和原因，可从失败节点修订恢复。所有已有空组完成后，校验合并库和话术实际可播性，再发布主库与现有格式的溯源文件。已有组可保留可用的历史溯源，缺少历史溯源时明确记录缺失。

## 指定案例及验收

1. 用 `knowledge/lineups/开备韩信-姜导.json` 初始化 `personal/template/initial/开备韩信-姜导.json`。这个位置保留指定文件名，并避开 `personal/template/开备韩信-姜导.json` 中已有的成品。正式阵容名是 `开备韩信`。复核英雄、拍卖轮次、天赋、装备与适用英雄、效果牌的组覆盖，以及固定条件和具名指令。
2. 将初始库和 `personal/开备韩信-姜导.md` 交给 `template_generate`，输出 `personal/template/开备韩信-姜导-v3.json` 及同名溯源文件。该 Markdown 是 v3 的笔记来源，扩充可引用已核实的卡面及规则数据。
3. 逐组对照初始库和 v3，验证原组结构一致、所有空组已补齐、已有话术保留。抽查主 C 战斗能力、拍卖预算措辞及装备适配解释。检查新增组来自指定 Markdown、有独立理由且能按条件播报，合并过程可追溯。覆盖旧库、混合库、已有组重合、重试恢复，以及 Markdown 和表格初始化入口。
