# 模板生成工作流的局势组扩充

在补全初始库空组的同时，多找出能解释具体局势的独立决策。用 v3 的初始库、个人 Markdown 和本地运行配置生成 v4。

## 扩充方式

单独放宽识别提示词能增加候选，但很难知道哪些段落、事件或局势已经检查。采用逐段覆盖和按关系追查的方式。工作流保存每段的处理结果，并把本次确实改变决策的局势连接到正式事件和模板组。用户已确认可以用本地卡面与规则推导笔记未明说的联动。原文依据、卡面事实和策略推导分别记录。

1. 逐段登记笔记，独立拆出每个动作、收益及适用条件。初始组继续按 `instruction` 补齐。
2. 对每项收益追查提供者、受益者和兑现时点。检查取得组件、使用组件、改变站位或运营节奏等实际可发生的入口。优先挖掘场上、手牌、觉醒、阶段、资源和对手等能影响取舍的事实。
3. 保存每条线索与原文、证据、正式事件和组 ID 的对应关系。证据不足、字段无法表达、收益已覆盖、事件不成立的线索各写明原因。覆盖清单有据可查后收尾，组数由独立且能验证的收益决定。

## 基础组和细分组

- 有现成基础组时引用其 ID，复用事件和适用的额外信息键。比如买亚连仍使用亚连的精确键，细分条件可检查手里是否有临阵磨枪，解释它让这次拿牌多创造哪一次整备机会。只检查手里有牌可以讲未来机会，已经兑现的收益另需证据。
- 新组使用正式 v0.5 条件。具体键已限定的对象无需在表达式里再判断。共享同一收益时，检查购买、选择、拍卖等实际入口是否齐备，并保留各入口自己的字段和必要事实。仅在某个动作成立的解释可独立建组。
- 每组通过求值和整库播报验证。保留同一动作，逐项替换或删除必要事实。适用时细分组应胜出，事实不成立或未知时应回到适用的基础组；动作对象错误时，两者均不应借此匹配。额外条件必须改变理由，每条话术都要说出这项额外收益或取舍。

## v4 交付

- 沿用 `personal/template/initial/开备韩信-姜导.json`、`personal/开备韩信-姜导.md` 和 v3 的本地审编配置。现有工作流在读取旧库时执行 v0.5 迁移，核对初始组的 ID、事件、键和条件含义。
- 输出 `personal/template/开备韩信-姜导-v4.json` 和同名溯源。对照 v3 的 64 个补全组及 5 个新增组，逐项报告实际覆盖、新增局势及有依据的遗漏理由。验收看不同决策和局势的覆盖、组间播报选择及逐句的信息量。
