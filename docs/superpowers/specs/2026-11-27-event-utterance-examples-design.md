# 按事件为话术生成加入人工样例

话术生成节点使用万象棋模板 Skill 的人工样例。每条样例明确列出正式事件、适用条件和人工话术原句。按照事件维护、核实和加载样例，让模型可以借鉴具体写法。

## 数据来源与维护

初始样例从万象棋模板 Skill 的人工案例一次性核实整理。工作流使用并独立维护 `workflow/template_generation/references/event-examples.json`，按正式事件增删并用工作流自己的事件定义校验。Skill 的案例库继续单独维护。

每条样例包含 `event`、`condition` 和 `utterance`。`event` 用正式注册名。`condition` 写明对象、阵容及影响这条话术的必要前提，有可验证的原规则时保留额外信息键和正式表达式。`utterance` 保留人工原句。另保留样例编号或原组、话术 ID 等来源定位，便于复核。

## 核实和接入

- 优先跟随稳定 ID 回查原组，把事件、键和条件核对齐。历史案例只有局面简述时，核对人工原文和正式资料后，可使用能完整限定这句话的自然语言条件。条件无法核实时，记下缺失事实，保留原案例以便以后补齐。重复样例合并来源。逐事件记录纳入、待核实和暂无样例的情况。
- 首拍和二拍按正式事件分别管理。只有来源明确轮次或可用原事件记录核实的案例，才加入对应拍卖事件。一个文档覆盖多个事件时，每条样例仍单独指定正式事件。
- 只在 `phrases` 阶段注入已核实样例。普通生成和空组补全共用相同入口。一次涉及多个事件时分组列出，只给本次实际生成话术的事件提供样例。参考原句的写法时，仍用当前知识、事件和条件核实可播内容。无样例的事件仍按现有事件策略生成。
- 将样例资源纳入工作流运行指纹。原始 prompt 溯源应包含当次注入的事件样例。验收覆盖普通生成、空组补全、同批多事件、首拍与二拍隔离、缺少样例及已核实原句原样传入。
