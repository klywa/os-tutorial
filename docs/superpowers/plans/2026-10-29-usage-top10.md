# 使用率Top-10 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; user approved the design and requested implementation.

**Goal:** 看板增加按外站组合登场率筛出的十个阵容＋棋手的覆盖矩阵。

**Architecture:** 独立网站适配器读取全榜/完整棋手列表，后台每日原子发布本地快照；只读匹配正式阵容名单及笔记，现有dashboard按scope聚合，React复用矩阵。

**Tech Stack:** Existing Python/urllib/SQLite/React/TypeScript/Vitest; no new dependencies.

**Spec:** 用户本轮批准的《看板增加“使用率 Top-10”筛选》。

## Global Constraints
- 最新版本、万象大赛、最近7天，每个阵容＋棋手至少50场；usage=阵容appearanceRate×棋手count/阵容count，不用sampleCount。
- 网站分组ID×棋手ID作为身份，先排名取10再本地匹配，不拿已匹配低名次补位；不足10用实际数量。
- 组成/既有变阵唯一匹配，来源关联要重新验组成；棋手ID+唯一primary笔记优先，否则唯一候选，无则missing，多则ambiguous。
- 全库篇数不变，选中组合覆盖分母为实际组合数×7；歧义暂未计已确认覆盖。
- 北京时间09:00随服务运行、启动补刷、失败30分钟重试、独立线程/跨进程锁、原子last-good；不改正式知识和人工关联，不提交Git。

## Review Focus
- 不能用条件棋手占比直接跨阵容排名，不能只抓前三棋手；接口字段及分页总数严格核验。
- 来源ID重用但组成变化不能继续自动匹配；主/变阵跨父有歧义不可强配。
- 旧全库scope兼容；首次无快照不能伪造0%；匹配歧义有独立状态。
- 网络任务不持知识写锁，不阻塞后台媒体任务，两个服务/手动刷新不能并发抓取。
- 快速切scope不能让旧响应覆盖新结果；Top10无笔记时格子不能伪跳转。
