# UP主列表误报为空

证据：本地数据库有4位UP主；127.0.0.1:8765的creators接口返回同样4位，当前用户Chrome页随后也已显示4位。没有删除或恢复数据库。

原因：Crawler.refresh使用Promise.all，必须等任务投影也成功返回才发布UP主列表。首次加载使用空数组显示“0/尚未添加”，任务请求慢或失败会让已有UP主看起来消失；2秒轮询还会叠加慢请求。

修复：两个列表独立发布；每个接口最多一条未完成请求；UP主明确区分加载中、读取失败与确认空列表；失败保留已有列表并提供读取重试。任务列表失败不阻止UP主列表刷新。不修改数据库、监听配置、后台任务或任何手动标注。

验证：新增crawlerLists.test.ts覆盖任务延迟、任务失败、UP主失败保留与慢请求去重；browser_monitor_resilience.cjs增加真实浏览器的延迟/失败场景。最终结果见temp/creator-list-*.log。

结果：3项新增测试、前端全套160项通过，生产构建通过；1440/390浏览器的独立加载、加载中不误报为空、失败保留列表和重试恢复通过。仅前端修改，不需重启后端，网页刷新后加载修复。
