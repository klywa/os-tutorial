# 事件与条件语法参考

模板组的 `utterances` 保存可供独立抽取的话术。可选的组级字段 `explanation` 保存供读者查看的「说明与依据」，至多 300 个 Unicode 码点（含标点）。导入、导出和编辑时按组保留这段文字。用自然语言交代触发场景、教学目的、来源位置和具体依据。事件匹配仍由适用范围及条件表达式决定。

一条规则先选定事件，再在该事件的参数作用域内写一个布尔表达式。事件参数描述动作发生时的对象或值；`玩家`、`商店`、`对局` 是动作完成后可查询的逻辑主体。点号沿属性取值，底层数据的存储和传递方式由接入方决定。

## 从一句需求写出条件

“刚上阵的英雄是当前主 C，主 C 至少 10 级，而且上阵后剩余能量不超过 3。”选定签名 `解释为何上阵英雄(arg1: 英雄)`，条件写成：

```text
玩家.主C.名称 is arg1.名称 and 玩家.主C.等级 >= 10 and 玩家.剩余能量 <= 3
```

假设上阵的是弈星，当前主 C 也是弈星、等级为 10，剩余能量为 3，结果为真。仅把主 C 等级改为 9，结果为假；仅让主 C 的等级未知，整条条件也不会命中。这里的 10 级来自当前主 C。若意图是“这次卖掉的是一名至少 10 级的英雄”，应选择 `解释为何从战场出售英雄(arg1: 英雄)`，写 `arg1.等级 >= 10`。即便英雄已离场，参数仍指向出售时的英雄。相同名称不会让不同路径共享动态属性。

## 事件声明与条件文法

以下 EBNF 用 `[ ]` 表示可选、`{ }` 表示重复、双引号表示实际字符。签名中的花括号、方括号等元符号不参与生成。

```ebnf
签名     = 事件名 "(" [ 参数 { "," 参数 } ] ")"
参数     = 参数键 ":" 类型
类型     = 基本型 | 命名型 | 联合型 | "Array<" 元素型 ">"
元素型   = 基本型 | 命名型 | 联合型
基本型   = "int" | "number" | "bool" | "string"
联合型   = 命名型 "|" 命名型 { "|" 命名型 }

条件     = 空文本 | 或式
或式     = 与式 { "or" 与式 }
与式     = 非式 { "and" 非式 }
非式     = "not" 非式 | 比较
比较     = 原子 [ 操作 原子 ]
原子     = 路径 | 字面量 | "(" 或式 ")"
路径     = 根 { "." 属性名 }
根       = 本事件的参数键 | "玩家" | "商店" | "对局"
操作     = "is" | "in" | "has" | "<" | "<=" | "==" | ">=" | ">"
```

- **名称与作用域。** 事件名按目录中的完整名称选取。参数键匹配 `[a-z][a-z0-9_]{0,63}`，同一事件内唯一。保留词为 `and or not is in has true false`。属性名按主体目录逐级解析，`name` 可写作 `名称`，其余按原名书写。标识符和字符串值区分大小写。
- **字面量。** 布尔值写 `true` 或 `false`。数字使用十进制，可含负号、小数或指数。字符串用双引号，按 JSON 字符串规则转义。列表常量如 `["弈星","小乔"]`、`[1,2,3]`、`[]`，元素为字面量。命名实体常量如 `{"类型":"英雄","名称":"弈星"}`。这些是表达式里的常量写法。`未知` 是求值状态，没有对应的条件字面量。
- **组合。** 从高到低依次为括号、比较、`not`、`and`、`or`，连续的与或按从左到右组合。一个比较只接受一个操作符。闭区间写作 `玩家.血量 >= 10 and 玩家.血量 <= 30`。纯空白条件视作真；非空条件必须得出布尔结果。括号和取反合计最多嵌套 64 层。
- **签名示例。** `解释为何刷新商店()` 无参数。`解释为何选择英雄(arg1: Array<英雄>, arg2: 英雄)` 有两个参数。`Array<英雄|效果牌>` 表示各元素可来自这两种实体类型。类型须来自目录；联合型的各分支均为命名实体。

## 类型判断与操作

| 操作数 | 可用写法 | 判定 |
| --- | --- | --- |
| 两个数值 | `< <= == >= >` | 按数值比较，int 与 number 可互比。字符串 `"10"` 不会转成数字。 |
| 两个布尔值 | `==`；布尔表达式可用 `not and or` | `not arg1.已觉醒` 判断未觉醒。 |
| 字符串、名称、枚举 | `is`；也可作为 `in` 的左项 | 按值精确比较。属性可以和同类型属性比较。 |
| 命名实体 | `is` | 按类型和名称识别，同类型下名称唯一。单一实体类型可简写为名称，如英雄参数 `arg1 is "弈星"`。 |
| 元素和列表 | `元素 in 列表`、`列表 has 元素` | 两种顺序含义相同，元素须与列表元素类型兼容，如 `arg1 in 玩家.手牌`。元素可以是数值、布尔、字符串或实体。 |
| 个别属性 | 以属性声明为准 | `装备.类型` 只允许 `is`。英雄伤害类型是封闭枚举，用常量比较必须取“物理”或“法术”；英雄定位允许扩展。 |

`商店.商店列表 has {"类型":"英雄","名称":"弈星"}` 查找英雄，遇到同名效果牌会区分类型。对于联合型参数，访问属性时该属性须在所有分支上存在且返回同一类型。例如 `card: 英雄|效果牌` 可读 `card.名称`；`card.等级` 无效。当前值恰好是英雄也不改变这条静态规则。

准备战斗时，`玩家.手牌 has {"类型":"棋手技能","名称":"小菟送福"} and 玩家.场上英雄数 < 4` 表示手中留有小菟送福且场上不足四名英雄。`玩家.人口上限` 是此时允许上阵的人数。两个整数由局面分别提供，均支持 `< <= == >= >`，缺失的字段按未知处理。

## 缺值、空列表与错误

属性合法但值缺失时得到“未知”。只有最终结果为真才命中。下表中 A、B 可交换，取反列只对 A 求值。

| A | B | A and B | A or B | not A |
| --- | --- | --- | --- | --- |
| 真 | 真 | 真 | 真 | 假 |
| 真 | 假 | 假 | 真 | 假 |
| 真 | 未知 | 未知 | 真 | 假 |
| 假 | 假 | 假 | 假 | 真 |
| 假 | 未知 | 假 | 未知 | 真 |
| 未知 | 未知 | 未知 | 未知 | 未知 |

空列表是一个已知值，成员判断为假。列表缺失时成员判断为未知。列表存在时，任一元素匹配就为真；没有匹配且至少一项无法确定则为未知。未声明字段、错误的操作数类型和语法错误应报告给作者。所有子表达式都须有效，`true or 玩家.未声明字段 > 0` 也会报错。

| 在“解释为何上阵英雄”事件中 | 结果或改写 |
| --- | --- |
| `arg1.等级` | 单独的数值不能作为条件，可写 `arg1.等级 >= 10`。 |
| `arg2.名称 is "弈星"` | 此事件只声明了 arg1。 |
| `arg1.名称 == "弈星"` | 字符串相等用 `arg1.名称 is "弈星"`。 |
| `10 <= arg1.等级 <= 30` | 拆成两个比较并用 `and` 连接。 |
| `not (arg1.已觉醒)` | 合法；缺少觉醒状态时仍为未知。 |

## 编写条件的验收方法

**同级命中时，优先采用条件更严格的组。** 如果 A 成立时 B 一定成立，而且存在 B 成立、A 不命中的情况，A 的命中范围就是 B 的真子集。两组同时命中时选 A。例如同为默认优先级 0，A 写 `玩家.剩余能量 <= 2`，B 写 `玩家.剩余能量 <= 3`。剩余 2 能量时选 A，剩余 3 能量时只有 B 命中。等价条件（如整数上的 `< 3` 和 `<= 2`）以及互不包含的条件保留同等机会。显式设置不同整数优先级时，较高者优先。判定比较的是条件表达式；事件和适用范围先用于筛选。

1. 选定一个已声明事件，逐个确认参数的角色、类型和顺序。例如“转移装备”中，原持有者与接收者都是英雄，须按位置区分。
2. 把每个判断写成“来源路径、操作、比较对象”。先判断需要动作当时的参数，还是动作完成后的主体属性，再选择路径。只组合目录中可表达的判断。例如“本局第一次购买”需要购买历史；现有目录没有这项属性，应记录缺少的数据能力。
3. 给规则配一个命中例、一个只改一项事实的未命中例、一个属性缺失例。对联合型，再配一个“名称相同、类型不同”的例子。用自然语言描述事实即可。
