# 模板库加载测速

2026-11-18，在同一台 Windows 电脑用 Chromium 打开真实本地服务，分别测试生产静态页（8765）与 Vite 页（5173）。正式库有 315 个模板组。生产页首次可筛选的中位时间从 17–18 秒降至约 1.1 秒，离开后再进入约 1 秒。

## 用户操作耗时

表中单位为毫秒，每格为三轮中位数，箭头左侧为改动前，右侧为改动后。

| 端口 | 浏览器缓存 | 首页首次可操作 | 首次进入模板库并筛选 | 离开后再次进入并筛选 |
| --- | --- | ---: | ---: | ---: |
| 8765 | 冷 | 1,671 → 437 | 18,283 → 1,068 | 8,766 → 938 |
| 8765 | 暖 | 227 → 212 | 17,190 → 1,090 | 8,205 → 991 |
| 5173 | 冷 | 1,640 → 651 | 11,460 → 1,774 | 8,601 → 1,251 |
| 5173 | 暖 | 594 → 632 | 12,134 → 1,194 | 9,403 → 1,039 |

5173 暖首页的中位时间增加 38 毫秒。三轮样本适合比较本机同一工作流，无法据此判断这 38 毫秒的差异能否稳定复现。

## 浏览器记录的请求耗时

每个端口合并三轮冷热样本，取 Resource Timing 中已完成的请求时长中位数，单位为毫秒。以下接口可以并发，表中数值不能相加为页面耗时。

| 接口 | 8765 改动前 → 后 | 5173 改动前 → 后 |
| --- | ---: | ---: |
| 模板快照 `templates` | 7,407 → 712 | 7,550 → 743 |
| 关联资料预警 `templates/warnings` | 8,748 → 71 | 7,133 → 83 |
| 模板同步冲突 `templates/sync-conflicts` | 1,728 → 908 | 2,067 → 924 |
| 笔记目录 `notes/catalog` | 623 → 84 | 706 → 51 |
| 笔记提案 `proposals` | 1,428 → 32 | 1,283 → 28 |

改动前页面会重复取得 918,212 字节的全量笔记提案。复测的首页及模板操作只观察到 70,357 字节的当前笔记提案请求。模板快照响应由 362,569 字节变为 362,761 字节。生产和开发页面都保留了全库筛选数据。

服务端按正式记录、事务、卡牌和阵容笔记索引的文件代际复用快照及实体资料。列表先显示首批 20 张卡片，滚动或使用「显示更多模板」可继续查看。预警在主体数据就绪后更新，全库搜索和导出始终使用完整结果集。

## 复测口径

1. 每个端口建三个新的浏览器上下文各测一轮。每轮首次导航为冷浏览器，同一上下文返回对局助手并重新导航为暖浏览器。后台服务在连续采样期间保持运行。
2. 首页从开始导航计至当前笔记的「导出整篇」按钮可见。模板库从点击导航开始，等待第一张卡片可见、在搜索框输入「周瑜」并清空。回到对局助手、等首页按钮可见后，重复模板操作测量再次进入。
3. 在第二次筛选完成时采集资源时间，记录接口名、毫秒数和解码后的响应字节数。这个时点之后才完成的后台请求不会进入样本。浏览器资源时间缓冲区也可能省略部分请求。

从项目根目录运行 `node frontend/benchmark_template_load.cjs temp/template-load-repeat.jsonl`，指定一个新的输出文件。脚本支持用 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH` 指定本机安装路径。本次原始记录位于 `temp/template-load-baseline.jsonl` 和 `temp/template-load-final.jsonl`。
