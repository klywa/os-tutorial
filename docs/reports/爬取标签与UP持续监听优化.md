# 爬取标签与 UP 持续监听优化

关键词、链接及 UP 监听支持多选采集标签，复用已有标签并可创建。后台持久队列将标签追加到来源最新人工覆盖中，保留原备注、忽略和入库状态；指定 P 的链接只给对应 P 追加，完整投稿覆盖全部已登记 P，后续生成的分 P 完成时重新补齐标签。

UP 默认使用监听名称标签，空名称回退平台作者或 UID。修改配置及旧监听首次迁移后台追补历史来源，列表显示待处理数量及失败重试。

每个 UP 对应唯一稳定任务；旧批次保留，通过成员关联聚合累计来源。暂停及恢复覆盖历史派发，重试历史失败项不解除扫描暂停。前端初始化恢复启用监听的暂停并安排检查，明确停用保持停用；并发请求合并，历史风控最长等待保留。持续任务通过监听停用或删除管理，不能直接删除活跃监听任务。

验证结果：399 项 Python、64 项前端、生产构建及知识 validate 通过。双入口隔离浏览器覆盖三个标签入口、指定 P、默认 UP 名称、稳定任务、刷新恢复暂停、保留停用，桌面及 420px 无横向溢出，0 页面异常。另覆盖删除后重新添加监听及历史任务兼容。

两个正式后端在采集空闲时更新，重启前后无活动转写。上线前备份队列和来源登记；正式 4 个 UP 各展示一个持续任务，249 项历史标签队列完成。对照备份，视频任务状态及 generation 检查点完全一致，444 条来源数量保持，原人工备注及其他覆盖字段保留，仅追加标签和更新时间。两个实际入口的启动恢复接口均返回 200，无页面异常。
