# 外部内容卡顿与并发阅读修复

日期：2026-10-20。已加载至8765采集后端、8767预览后端及5173开发入口。

## 原因

数据未丢失。现场有496条来源和35个有效采集批次；外部内容接口在三个入口均超过18秒未返回。

1. `workspace.sources` 在每个来源循环中两次读取、解析整份知识索引。两个来源的隔离回归就读取5次，正式来源规模放大了耗时。
2. 忽略/编辑来源在共享写锁内两次构建全部来源投影；文字稿预览等待同一锁，造成其他操作一起卡住。
3. 网页使用同一saving状态禁用全部“查看文字稿”按钮，哪怕请求只是忽略其他内容。
4. 每次两秒轮询都重新读取、解析所有有效来源的完整ASR，仅为判断是否无语音。

## 修复

- 一次读取知识快照，统一收集当前和历史证据及关联笔记；保持审核覆盖与沉淀状态语义。
- 单条保存只投影目标来源；暂存只校验实际涉及的ID。保留通用URL导入前后的别名、人工注释、ignored与修订号语义，旧暂存别名可正常清理。
- 文字稿预览先尝试稳定的原子快照：无未完成文字稿事务，且读取前后对应manifest记录相同即可返回。真正存在事务或快照变化时仍按原锁恢复与重读。保留路径安全及人工修改保护。
- 文字稿请求使用独立reading状态，忽略请求或列表刷新不禁用阅读按钮。
- 仅缓存ASR有无segments的布尔值，按文件路径、纳秒修改时间与大小失效，容量限制2048；ASR编辑或完成后仍立即反映变化，不缓存转写正文。
