沿当前知识的收益向前和向后检查实际决策，逐项与随附的正式事件、动作对象、事件特殊标准与策略、常见条件与话术内容比对。相同收益检查所有可发生入口，区分当前收益与将来机会，记录排除原因。每个关联事件用 expected 写本事件预期向玩家说明的取舍、对象、收益与时机。只返回来源证明且正式注册的事件。无可解释入口时，events 留空并在 excluded 写理由。
每个事件另给 base。先拿掉天赋、装备、库存、觉醒等附加条件，判断剩下的收益能否独立解释当前动作。若能，用 base.expected 讲这个基础收益，base.fields 列出表达最小触发所需的正式字段路径（含动作对象；聚合谓词字段如 .名称 也要列出）。若收益只在附加条件下才成立，base 为 null。当前事件新增的细分理由仍写在 expected 中。购买、选择、竞拍等入口分别判断。以购买阵容主力为例，阵容和所买英雄就能证明补主力的理由时，场上库存与额外天赋均不进入基础条件。
保持补充知识的 type 和核心问题。随附的当前知识类型常见事件可用于查找入口，是否采用仍由实际收益与正式事件字段决定。参考资料里的其他独立收益不作为当前点的事件依据。
七类映射
1. 英雄作用检查购买、选择、两轮竞拍及关键英雄到位后的阵容发展。
2. 天赋作用检查选择天赋和关键天赋支持的阵容发展。
3. 装备作用检查穿戴、铸造（合成）、转移与阵容发展。
4. 效果牌作用检查选择、购买、第三轮拍卖和使用，区分玩家指定目标与随机受益者。
5. 棋手能力检查选择、使用技能与阵容发展。
6. 运营节奏检查刷新找什么、升到几级做什么、准备战斗为何留牌或留能量、成型后怎样提升。
7. 技巧对策检查购买对策英雄，合成或转移对策装备，出售英雄刷牌、集中登记、腾出打出位等原文可证的实际目的，以及准备战斗等待的时机。
