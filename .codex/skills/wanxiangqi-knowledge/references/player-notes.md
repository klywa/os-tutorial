# 棋手笔记

## 章节与内容边界

正文顺序为：技能 → 前期思路 → 适用打法与选择 → 适用技巧 → 关联知识。标题和文件名只使用棋手名，如“昭君”“闹闹”，每位棋手只有一份type=player笔记，以player_id绑定官方棋手实体。保留稳定笔记ID；旧描述性标题作为搜索别名，迁移路径后同步关联链接与重放，旧文件留恢复副本后退出活动目录。旧“使用技巧”归入“适用技巧”；删除“适配阵容”标题，其有效内容迁入选阵说明，不直接删结论。尚无完整教学的打法留在“其他已知方向”，说明未整理范围，不创建虚构阵容链接。

新建、编辑、导入、共享保存均按player_id判重，不能靠换标题另建笔记。网页选择棋手后自动命名；已存在时打开原笔记。技能收到新材料先按身份检索复用旧ID；旧导入可从原绑定或唯一明确的棋手实体补齐身份，多个候选或缺失时报冲突，不从正文提及或描述性标题截断猜归属。运行`wxq.py migrate-player-identities`迁移既有资料，重复执行幂等。不为未整理棋手自动生成空笔记。阵容—棋手笔记仍属阵容类型，不与棋手唯一笔记混同。

“前期思路”面向尚未定阵的局面：技能使用、过渡质量、经济与棋手升级、观察来牌及定阵信号。先核实建议能否跨阵容成立；仅在某阵容中成立的尽快将棋手升至五阶、固定名单或卖血路线继续放在该打法。可从已有机制与策略推导时保留条件并标记inference；不足以概括时明确通用开局尚待确认，并在交付中列缺项。不能把一场胜利当作棋手前期必强，也不能因一个阵容后期成长高就断言棋手所有阵容后期都强。

“适用技巧”保留技能操作、资源管理及跨阶段技巧；专属阵容的技巧注明条件。与前期思路重复的内容合并，有不同阶段含义的复合结论可拆分并记录derived_from。技能机制与技巧的来源、人工历史保留。

## 适用打法与技巧的段落格式

“适用打法与选择”每套阵容只保留一个可见entry，key使用阵容名，不再以阵容子标题搭配多条字段。value按下列顺序写成一个自然段，不含换行、子列表或嵌套标题：

必须阵营：… 关键成员：… 定阵条件：… 主要英雄：… 核心机制：… 优势：… 短板：… 阶段强度：前期…；中期…；后期… 可能变阵：…

- 必须阵营：体系成立所必需的阵营，排除仅因过渡或可选成员涉及的阵营；没有已确认要求时写“尚待确认”，不能将无资料写成不受禁用限制。
- 关键成员：构成体系的核心、辅助及配合，区分必需和条件成员。主要英雄：输出、承伤或成长投入对象及职责；同一英雄可同时涉及两项，但两项回答不同问题。灵活变阵不强行补固定名单。
- 定阵条件：保留来牌、资源、觉醒、同行与血量等有据判断，以及放弃或转向条件；回合数和投入门槛只使用直接证据或明确记录依据的推导。原“英雄投入”等独有内容归入对应条件、主要英雄或机制，不能为缩短段落删除有效操作。
- 阶段强度：前中后期均说明当前战力、形成强势的条件及空窗风险；缺项写“尚待确认”。不能把某一分支的判断推广到整个棋手。
- 可能变阵：写清转成哪套打法、什么情况下转及原因；只有换单个工具位时不冒称另一套打法。没有可靠依据统一写“暂无已确认的变阵方案”，不把同棋手可玩列表当成互转关系。

其余缺项统一写“尚待确认”。段内字段直接使用“标题：内容”，字段之间以空格衔接，不加【】等装饰括号；保留正文中的有效链接或代码语法。关联阵容链接集中保留于“关联知识”，目标必须实际存在；尚无完整教学的已知方向仍可说明边界，不伪造阵容链接。

“适用技巧”每条一个可见key-value条目，key为明确的技巧名，value为单段自然语言；保留条件、具体对象、操作顺序和原因，不强制套【条件】【操作】【原因】标签，去掉原段首列表符号。保持原有清楚的表达；仅在实际独立决策不同时拆条，不为统一格式把同一技巧重复写入多个阶段。

合并前记录原节点的内容去向。沿用仍承担相同含义的稳定ID；新摘要关联实际依据，原结论及证据可作为supporting_nodes保留并建立依赖，不能将旧结论改义后继续冒用单一旧来源。人工保护和并发规则照常执行；不可把未承接的有效内容或未裁决冲突移到内部后声称整理完成。章节之外的内容保持原样。

## 组合阶段强度的同源数据

schema6的阶段强度依据保存在当前绑定阵容正文的`semantics.selection.stage_strength`，按early/middle/late保存阶段说明及claim_refs、inference；相同文本通过$text引用节点，不另存一份可编辑正文。依据只能引用该棋手可用的共通或专属结论。未整理的阶段允许缺失或空text，棋手整段显示“尚待确认”。人工修改某阶段只更新该阶段依据并记录人工来源，原依据留在编辑历史；其他阶段保持原样。旧schema5的player_branches字段只用于历史迁移。

棋手的`lineup_adaptations`是兼容读取投影；schema6以正文和$text引用为准，不单独维护一份阶段判断。每套打法在整段value的“阶段强度：…”中列出前中后期定性说明：现有战力、组件／成长条件、强势窗口与空窗风险。不打分，不编造回合、等级、相对胜率；只有来源明确时才使用具体门槛。资源或技能未来收益不等于当轮战力；不同开局、技能路线的条件分别说清。

转换原有选阵表格或多条字段时，保留stage_strength等未涉及的语义与证据，前中后期说明归入同一阵容段落的阶段强度标签。引用合并、删除或分支复制时同步重映射，禁止引用其他棋手的专属结论。新旧章节名不能同时保存相互冲突的正文；保留草稿并提示合并。

## 保存与验收

复用已有资料时，不默认补采或同步官网。先恢复事务并读取最新正文、附件及revision，保存变更前快照；通过schema6统一commit维护成对正文与附件和轻量索引。只有本次证据实际影响的阵容一并提交；仅格式整理不扩大到阵容正文。不恢复旧Markdown同步、分支文件或重放写入入口。

核查五章节顺序、九项单段与命名技巧、旧选阵独有内容及来源／人工保护／稳定ID；每个组合三阶段说明或明确缺项；阵容更新同步其棋手摘要；旧编辑保留新增字段；重复保存不增长；网页、复制与即时导出同源，旧章节定位兼容。运行相关测试、构建、skill格式校验及wxq validate，交付逐棋手缺项、实际证据范围和未决冲突。不生成知识Markdown或宣称支持其自动回读。
