# 验收场景

棋手唯一身份与升级教学：棋手名标题／文件名、player_id唯一、旧ID与人工历史保留；网页选择棋手，已有项可打开原笔记；创建／编辑／导入／共享保存、并发与请求重试不能制造第二份。身份缺失或歧义报错，原路径备份后退出活动目录，关联与重放更新，重复迁移幂等。逐阵容×棋手×路线核查一至六阶行动、找牌、停留及升级判断，缺证据明确留缺，不以固定回合代替判断；正式阅读统一棋手等阶术语，原始转写与历史不改。桌面／窄屏检查创建、重复提示、目录、关联跳转及升级段落。

## 文字稿复用及逐英雄提质

- 已有完整ASR／字幕全文直接读稿，不触发下载、模型、prepare或重复导出；指定P匹配准确，其他P缺稿不误判齐备。
- 已登记人工全文可读可复用，未登记外部修改保留并报告；预览、截断、损坏、无语音记录不冒充完整教学。底层档案缺失只阻止未经校验的提交，不覆盖全文。仅缺帧按需补帧。
- 每个实际阶段成员均有具体机制、对象、作用，觉醒四档及理由或明确待确认；每个后期组合成员均有等级三档及理由或待确认。不同路线独立，不把必需成员等同必须觉醒，不把等级强化节点等同永久等级停点。
- 有据推导保存inference和真实依据；没有技能资料不臆测，既有来源、稳定ID、人工章节、历史和排除条件保留。统一保存与重建后role、阶段正文、各棋手分支和重放一致，不重复追加同义策略。

笔记目录与创建验收：知识目录仅展示笔记，空阵容名单不进入目录，旧选择恢复到主/唯一笔记或合理回落；搜索浮层内部移动不关闭、外部失焦/Esc关闭且保留筛选，类型切换计数一致且不改变当前阅读。三类型空笔记创建、同类型同名、请求去重、并发和中断恢复不制造多份记录，失败保留草稿；旧来源分类继续可用，未使用的知识内容与人工历史哈希不变。

棋手笔记额外验收：技能／前期思路／适用打法与选择／适用技巧／关联知识顺序一致；旧适配内容无丢失，未定阵开局不混入专属路线；每个组合前中后期强度或缺项明确。阶段引用限定当前分支，选阵旧表格保存不丢新增字段；人工改某阶段只清除对应旧依据，历史保留。验证同源摘要更新、重复生成、旧章节定位、新旧名称编辑兼容及非目标笔记不变，来源核查与推导说明分别记录。

版本3表达额外验收：顶部身份保留、正文无重复棋手选择前提；条件与行动同段，双向编辑后不叠加，推测仍可见；后期当前方案成员仅打印一次，条件工具位在正文与概览均为备选；效果牌逐张列作用及获取／使用建议，天赋不混入。验证v2记录、外部编辑与三方冲突迁移，保留证据及人工历史。共通编辑同步所属分支，专属修改不扩大传播；JSON、正文、同步基线与重放一致。

## 来源、编辑与导出标准回归

按 [editorial-standards.md](editorial-standards.md) 核对以下语义场景；这些检查不是把案例日期和阵容名单硬编码成通用过滤器。

| 场景 | 预期行为 |
|---|---|
| 用户指定北京时间含当天的截止线、标题声称国一/95%胜率 | 正确转换边界，保存元数据获取时间；不凭标题认证作者、胜率或版本 |
| 用户排除一套打法，其他视频也混合讲到它 | 移除活动机制、路线、组合、站位及依赖；保留独立适用策略与历史，其他阵容同名英雄知识不受影响 |
| “缺少的河洛配套”“生存装”影响购买决策 | 从该段依据及阵容清单给出具体名称、必需/可选与条件；缺依据不补固定名单 |
| 禁用/对局摘要位于后期英雄清单下 | 归入禁用和对局章节，英雄清单保留成员作用、觉醒、后期等级投入与替换 |
| 多路线重复输出同一条结论 | 共通流程只展开一次，路线表保留差异；每条结论有主要展示位置，未知/人工结论不丢失 |
| 纯措辞与版式修改后重建导入 | 稳定ID及原证据保留，重放不恢复旧文本或被排除打法；非目标笔记正文及数据不变 |
| 仅含剧情/宣传/音乐或单场获胜 | 报告无可复用策略，不填假知识、不伪造零段文字稿及finish |
| 参考既有HTML导出，手机端隐藏对比表 | 桌面风格匹配；420px与打印有等价完整卡片/表格，结论不丢；目录、打印按钮和截图检查通过 |
| 仅请求HTML或优化现有知识 | 复用已核对材料，不自动重下载/ASR，不默认扩大前端/API变更范围 |
| 前端与HTML/Markdown存在不同阅读实现 | 同源章节顺序及每条结论一致，全文一次展示，速查按相同目录切换；路线找牌与棋手升级字段齐全，旧章节迁移、保存重载更新，其他笔记不受影响 |

既有`test_lineup_layout.py`覆盖专属版式的章节归位、原对象不变、正文一次展示、未映射结论可见及其他阵容保留旧版式；不能用这些单元测试替代来源、名称、冲突等语义核查。HTML导出还需真实浏览器验收，未执行时不声称已通过。

阵容教学覆盖验收：全部教学模板均有语义检查入口；相同内容在已有章节或 meta 中不重复入库。关键牌判断区分自用、工具及对手关键牌，不把单局持牌数量变成固定规则；战斗获胜、当局试探和单句“来不及”不能生成战后诊断或倒计时策略。空章节不计覆盖，有效 meta 不因正文占位被漏算；来源冲突标为部分覆盖并保留待裁决。新增可复用策略通过统一 commit 保存，缺证据只报告缺口，不更改固定字段或 meta schema。

新增验收：官网技能和强化节点、攻速/暴击单位换算、普通与觉醒来源区分；部分同步失败保留卡牌资料。卡牌库名称/效果/类别/阵营/英雄品阶/觉醒筛选及详情在完整窗口和420px侧栏可用。

关键辅助参与必须阵营，过渡和可选英雄排除；必须阵营被禁不可玩，多禁用组合保留unknown逻辑，人工meta不自动覆盖。刘邦必须大河和逐鹿；昭君必须大河，司空震可选。

两来源全文补录保留全部ASR段落与原始文件；拒绝错误时间顺序，保留合法段落边界重叠。疑词/转写间隔可见；重复导出幂等，人工修改产生差异报告。未导出或摘要过期时finish/validate拒绝通过。

网页升级额外验收：中文迁移幂等、同名中文序号与非法字符、手写旧文及证据保留、阵容 JSON/Markdown/索引一致、人工章节和 meta 导入保护、版本冲突、写锁与事务恢复、并发读请求、来源链接去重及分 P、处理与沉淀状态分离。运行扩展 Python 测试及 `frontend` 下 `npm test`、`npm run build`。

浏览器检查完整窗口及 420px 侧栏：阶段切换保持打法、禁用阵营多选及待确认结果、后期和针对策略速查、编辑预览/取消/保存、未保存提醒、全笔记分类与关联跳转、来源登记及修改。浏览器测试数据仅放隔离目录，不能把示例策略或来源加入实际知识库。

执行项目虚拟环境中的 `python -m unittest discover -s .codex/skills/wanxiangqi-knowledge/tests -v`，然后用真实攻略导入验证语义输出。单元测试的模拟内容仅在隔离临时目录出现，不进入正式知识库。

| 场景 | 观察结果 |
|---|---|
| 多链接中一个412 | 保留失败原因，继续其他来源；失败来源未完成 |

| 两阵容共享英雄 | 检索命中相关旧知识，Codex检查语义补充，双向链接更新 |
