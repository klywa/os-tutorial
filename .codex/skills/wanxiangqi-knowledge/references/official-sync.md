# 官方棋手资料同步

执行 `python scripts/wxq.py --root <项目根目录> sync-entities` 只更新本地官网缓存、卡牌和快照，不创建或修改正式笔记及知识索引。前端立即检查、重试和每日任务也遵守此规则。读取返回的 errors 及 `raw/official-sync/state.json`；成功需缓存发布完成，不能只看抓取完成。

仅当用户明确要求将官网资料写入笔记时，执行 `sync-entities --apply-notes`。它使用当前笔记重新合并，即使资料此前已经拉取，也会检查尚未应用的官网变更。旧事务中的笔记更新只归档到 `raw/official-sync/pending-notes/`，不会在读取、重启或重试时重放；这些快照用于审计，不应直接覆盖最新笔记。

引擎从官网当前页面的 cards.js、role.js 发现数据入口，保存来源地址、获取时间和原始响应到 `raw/official-sync/runs/`。遍历每位棋手的技能分组、关联牌与多层选项；按官方 ID 合并，循环只渲染一次并保留关联名称。专属天赋仍属于天赋类别，并关联所属棋手。

在现有技能章节组织官方技能、秘技、专属天赋和关联选项。明确区分等级、回合、累计次数和概率；未知字段语义标待确认，不从费用或品阶猜解锁条件。首次语义整合仅使用已核对且匹配当前节点 SHA256 的 reconciliation，变化后的旧节点完整保留为补充，不能仅按同名吞并人工内容。

`official_profile.nodes` 是官方管理边界。仅在显式使用 `--apply-notes` 时，这些节点以官网为准，即使被人工编辑也可更新，并保留旧正文、证据和完整历史快照。其他人工补充和策略内容继续保护。官网变化可能影响策略时查看报告的 `review_required`，核对证据后另行修订，不能自动编造策略。

缺组、关联缺失、未知类别、同 ID 冲突或请求失败保留既有正式数据并记录重试原因；缺失响应不能当成删除。重复检查只更新时间和报告，不制造正文版本。原始快照、历史和任务状态位于被 Git 忽略的 raw 下。

本地服务默认每日按爬取设置的北京时间检查；停机不执行，启动时补检最新窗口一次。前端可暂停、立即检查和重试。CLI 与服务共享跨进程锁；不要另设绕过锁或写入入口的定时脚本。

升级前无 origin 且无正文版本的元数据事务无法可靠区分人工修改与自动别名，因此保守归档供人工检查。若旧官网事务中断在正文、附件、索引之间，从已有备份在 `raw/official-sync/deferred-baselines/` 保存一致的旧版读取基线，不自动回写正式文件；后续显式应用使用该基线与当前官网资料重新合并。
