# 官方棋手资料同步

执行 `python scripts/wxq.py --root <项目根目录> sync-entities`。读取返回的 errors 及 `raw/official-sync/state.json`；成功需共同提交清单恢复完毕，不能只看抓取完成。

引擎从官网当前页面的 cards.js、role.js 发现数据入口，保存来源地址、获取时间和原始响应到 `raw/official-sync/runs/`。遍历每位棋手的技能分组、关联牌与多层选项；按官方 ID 合并，循环只渲染一次并保留关联名称。专属天赋仍属于天赋类别，并关联所属棋手。

在现有技能章节组织官方技能、秘技、专属天赋和关联选项。明确区分等级、回合、累计次数和概率；未知字段语义标待确认，不从费用或品阶猜解锁条件。首次语义整合仅使用已核对且匹配当前节点 SHA256 的 reconciliation，变化后的旧节点完整保留为补充，不能仅按同名吞并人工内容。

`official_profile.nodes` 是官方管理边界。用户已授权这些节点以官网为准，即使被人工编辑也可更新，并保留旧正文、证据和完整历史快照。其他人工补充和策略内容继续保护。官网变化可能影响策略时查看报告的 `review_required`，核对证据后另行修订，不能自动编造策略。

缺组、关联缺失、未知类别、同 ID 冲突或请求失败保留既有正式数据并记录重试原因；缺失响应不能当成删除。重复检查只更新时间和报告，不制造正文版本。原始快照、历史和任务状态位于被 Git 忽略的 raw 下。

本地服务默认每日按爬取设置的北京时间检查；停机不执行，启动时补检最新窗口一次。前端可暂停、立即检查和重试。CLI 与服务共享跨进程锁；不要另设绕过锁或写入入口的定时脚本。
