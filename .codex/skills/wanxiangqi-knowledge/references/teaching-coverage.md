# 阵容教学主题覆盖检查

整理新阵容、补充旧阵容或用户要求检查教学覆盖时使用。先读相关 Markdown、索引 claims、人工修订和 meta 运营路线，再按下表逐项检查。表中的 ID 对应项目 `proposal/tutorial/templates.json`；该文件存在时核对最新定义，模板更新后同步检查新增主题。不要从报告频次推导策略重要性，也不要把教学事件的分类当作知识入库许可。

## 三类容易漏掉的内容

**关键牌出现。** 分别检查自己需要的关键英雄、效果牌和装备，钟馗、太乙真人等工具牌，以及对手确实需要的关键牌。记录“这张牌当前帮谁、解决什么，拿还是放，拿后怎么处理”。只有来源明确讲到时才记录金币、手牌或上场空间、分走成长收益、库存与竞争成本。不要把工具牌写成每局必拿，不将对手关键牌留手的单局数量或效果写成固定公式。区分牌出现时的判断、缺牌时的替补、预算、拍卖竞价、具体操作顺序与对手威胁。

**战后诊断。** 查找讲者对伤害、存活、技能释放、实际接敌与预期不一致的解释，以及补牌、换装或调站位的可复用理由。单局“这轮输出更高”“赢了”“下轮再试”不能独立形成通用诊断流程。看不清、原因未知或只有当局猜测时，留内部报告；不同来源和条件的结论不拼成未经讲解支持的检查清单。

**操作时间不足。** 只有明确的时间压力及可复用取舍理由，才整理哪些动作必须先做、哪些可延后、何时不用继续精算。仅有“来不及了”或画面倒计时不支持优先级策略。不可把通常的技能顺序、棋手升级预算或暂不使用工具牌自动归入时间压力。

## 覆盖结论与补充边界

**主要变阵。** 按[主要变阵规范](major-variants.md)检查采用条件、与共同主干的六维差异及转入限制。核心不变但完整体系变化也可成立；只有棋手升级快慢、挂件或决赛圈工具位变化不算。证据不足的候选留待确认，不将检查主题等同于必须补齐变阵。

- 已覆盖：存在明确情境、行动与理由，可以回答该教学问题；不代表全部局势或数值已确认。
- 部分覆盖：已有相关内容，但关键维度缺失，或来源冲突仍待裁决。列明已有结论和具体缺口。
- 未覆盖：没有可靠策略。空章节、“暂无已确认的通用策略”、仅提到英雄及 `match_action` 不计覆盖。
- 不适用：有明确的阵容或机制边界依据；不能仅因来源没说而判不适用。

检查结果引用稳定笔记 ID、claim ID／章节或明确的 meta 字段。正文空章节但 meta 有有效策略时按整篇语义判断。规范允许承载主题和已入库内容是否覆盖主题分别检查。

补充前读原始及修正版转写的前后文，并核对需要的画面；保留来源、版本、条件及人工保护。既有结论已经回答问题时复用，不另加一份改写。真实新策略通过统一 commit 保存；不要复制别的阵容建议来填缺口，也不要因教学报告中有案例就将单局操作泛化。用户请求补充时尽可能核查现有证据；仍不足的逐项说明待确认理由，不自动搜索新攻略补齐。
