# 王者万象棋知识整理

用户提供本地文档时，先按[本地文档融合](references/local-documents.md)读取真实全文、登记文件快照和段落证据；不运行视频下载或ASR，也不把段落编号伪装成视频秒数。通用棋手知识与阵容分支双向审查，冲突留待用户裁决，无冲突内容继续提交。

接收一个或多个攻略链接，完成“登记并查找已有文字稿 → 按需获取素材或转写 → 术语与画面核对 → 分类 → 更新相关知识 → 校验”。已有完整文字稿直接用于知识提取，不重复下载或ASR。下载和转写由脚本执行，语义判断、纠错确认及关联内容补充由使用此技能的 Codex 完成，不需要云端 LLM/ASR 密钥。

## 路径与命令

以本技能所在的 `.codex/skills` 的项目根目录为默认目的地，不以当前终端目录猜测。`knowledge/`、`entities/`、`raw/` 与 `.codex/` 同级。视频处理档案放在 `raw/sources/BV编号_pN/`，全文文字稿仍放在 `raw/BV编号_pN.md`；`raw/` 不纳入 Git。`knowledge/` 保存整理后的知识与来源登记。允许显式 `--root` 指定其他项目。不要写到个人全局知识库。

以下 PowerShell 命令在项目根目录执行；其他目录使用完整路径。首次或环境缺失时运行安装脚本（会安装依赖并下载模型）：

```powershell
powershell -NoProfile -File .codex/skills/wanxiangqi-knowledge/scripts/setup.ps1
& .\.wxq-runtime\Scripts\python.exe .codex/skills/wanxiangqi-knowledge/scripts/wxq.py init
& .\.wxq-runtime\Scripts\python.exe .codex/skills/wanxiangqi-knowledge/scripts/wxq.py sync-entities
& .\.wxq-runtime\Scripts\python.exe .codex/skills/wanxiangqi-knowledge/scripts/wxq.py prepare '视频链接1' '视频链接2'
```

需要ASR时默认 `large-v3`、中文、CPU int8；可用 CUDA 时启用 GPU。首次模型下载可能耗时。已有ASR或字幕全文均可复用；缺少全文时按下文字幕优先与ASR回退规则处理。不要因速度悄悄更换小模型；用户明确要求时可用 `--model`。

## 整理流程

新建、修订话术或整体提质阵容先读[教学表达v4](references/teaching-v4.md)：核心原理先讲胜利手段，逐卡说明角色、相关效果和具体因果；标签按需，不为填模板重复购买、上阵或风险提醒。该文件统一规定自包含、冗余删除及章节归位，替代下文旧版阅读表达；保留v4布局、内部证据及既有记录兼容。

既有版本3阵容—棋手笔记兼容版本2语义目录；新建或整体刷新按上述v4规范。保留顶部身份，正文不重复选择或推荐已绑定棋手；实际条件与行动同行，后期先基础方法再条件调整。逐英雄作用、觉醒四档、后期等级三档的机制边界见[棋手分支规范](references/player-branches.md)。制敌手段表示如何应对对手，克制手段表示对手怎样克制本阵容。按棋手逐字段核查资料，缺证据不编造优先级或预算。有据推导保存inference和可追溯依据，正文说明机制理由，不能冒充视频原话。共通知识、结构化资料、网页与各棋手Markdown必须同步修改。

阵容笔记采用共通内容与显式棋手分支。修改已有阵容前，先读 [棋手分支与同步规范](references/player-branches.md)。**网页、结构化信息和 Markdown 必须通过统一保存流程同步修改**；不能只改一处后把其他生成物留旧。直接编辑固定格式的棋手 Markdown 后，运行 `wxq.py sync-markdown` 或由本地服务自动同步，检查同步问题后再提交。不得按正文中出现的棋手名推断归属，也不得把未分类结论默认归为共通。

开始整理或修改已有攻略前，读取 [references/editorial-standards.md](references/editorial-standards.md) 的任务范围、来源筛选、名称具体化和内容组织规则；仅在用户要求HTML时读取其中的HTML导出部分。日期、排除打法及参考版式按本次用户要求记录，不从某次案例推成全部任务的默认条件。

1. 读取 [references/workflow.md](references/workflow.md)。检查上次失败报告及相关来源状态，先通过共享恢复入口恢复 `pending-save.json`，再恢复 `pending-commit.json`。收到视频链接后默认通过 `workspace.register_source` 登记到 `knowledge/source-registry.json`，无需用户额外要求同步“外部内容”；按规范化链接去重，保留已有人工标题和备注，未知标题留空，获取元数据后仅补充空标题。登记后再获取素材，失败也保留记录。具体调用见 workflow 的“默认外部内容登记”。
2. 实体为空时先同步官网；用户要求更新实体或遇到未知术语时再次同步。查看 `entities/sync-report.json`：缺失类别不能表述为已完整同步。公开页面结构变化时读取保存的 HTML/JS，或用浏览器查找页面实际加载数据，再修正导入器；不要猜测接口或实体内容。
3. 先按规范化BV和实际分P检查 `raw/index.json` 及对应全文，按[文字稿优先分流](references/workflow.md#文字稿优先分流)判断。完整、可读且身份对应的已有文字稿直接用于知识提取，保留人工修订，不先运行prepare或export-transcripts。预览、无语音记录、缺失及损坏文件不能冒充完整教学。仅缺画面时按需补帧，不重跑全文转写；缺少可用文字稿才恢复既有阶段或用 `prepare` 获取素材。失败时保留报告并继续其他链接；来源失败不能标为完成。同一命令可重新执行恢复已有阶段。
4. 逐段读取转写与纠错候选，结合实体描述、前后文和对应关键帧处理同音及口语。原始 ASR 不可改写。更改修正版时在 `corrections.json` 记录原词、标准词、实体 ID、时间戳、判断理由和证据。歧义保留原文及候选。只有经证据确认的映射才能写入实体 `aliases`；不要将可疑词加入全局映射。
   术语标准化不等于更新游戏数值：旧视频的比例、回合或技能效果与当前官网不同，先核对视频原话，内部保留版本及官网来源；知识正文集中说明影响打法的差异，不用当前数值冒充ASR纠错。
5. 查看相关阵容、拍卖、装备、天赋、站位和终局画面。脚本初步最多抽取 80 帧；按需用 `frames SOURCE_ID 秒数...` 补帧。对实际看过的帧设置 `reviewed=true` 和具体 `observation`。纯画面信息在内部证据中记录帧，不在知识正文展示；看不清写待核实，不根据模糊缩略图猜英雄。重要数值或低可信度 ASR 需回放对应音频片段核对。
6. 自动判断阵容、棋手、其他，可一视频多条知识。读取 [references/knowledge-contract.md](references/knowledge-contract.md)；整理或补充阵容时，再按 [references/teaching-coverage.md](references/teaching-coverage.md) 检查教学主题，包括关键牌出现、战后诊断和操作时间不足。按下文通用策略规则筛选，在索引中为结论保存准确来源和时间段。检查主题不等于必须补齐策略：没有可靠通用内容的必需字段写“暂无已确认的通用策略”，其余缺口记录为待确认，不以实战事件填满模板。只有明确通用讲解依据才能写具体回合。推断用自然语言说明。发布日期不等于游戏版本。
7. **写入前必须扫描关联知识**：使用 `related` 按涉及实体、阵容核心及主题检索，并读取候选 Markdown 与索引结论。同一阵容/棋手主题复用已有条目 ID。检查实体提及全文以发现未索引旧笔记。补充本次证据确实影响的旧条目，所有新增和旧条目更新放入同一提交文件。仅增加关联链接不能替代语义补充。
8. 用 `commit FILE.json` 校验并合并。同文同版本同条件合并来源；不同版本、条件和无法解释的冲突并存，必要时增加“冲突与适用条件”结论。新视频不能覆盖旧结论。提交自动更新双向关联链接、索引、Markdown，修改前保留 `.bak`，中断时重放待提交文件。
9. 检查所有输出、来源、版本与引用。复用的完整文字稿只读核对；新增或实际修改纠正版后才运行 `export-transcripts SOURCE_ID`，检查全文及待核实项，不覆盖人工全文。创建来源目录中的 `review.json`：`approved=true`、实际核对的时间段、未解决问题和说明。调用 `finish SOURCE_ID`：要求已提交知识、有效原始及修正转写档案、有效文字稿及被引用帧核对记录；文字稿存在不代表审核或沉淀完成，缺档案先恢复，不绕过校验。成功后删除临时音视频，保留转写和帧。`approved` 是 Codex 完成核对的记录，不要求用户逐条批准。

## 中文知识与网页共同维护

新增知识以笔记为入口，不再先建阵容名单。网页“新建笔记”只需类型、中文名称和别名，正文与阵容资料后补；空白笔记不代表已有攻略依据。skill导入仍先检索复用同主题笔记，旧名单只用于采集主题兼容，不因其存在就自动创建知识。接口与重试规则见[知识契约](references/knowledge-contract.md)。

整理棋手笔记时读取[棋手笔记写作规范](references/player-notes.md)：以player_id保证每位棋手仅一份笔记，标题与文件名仅用棋手名，不加教学主题后缀，旧标题保留为搜索别名。按“技能、前期思路、适用打法与选择、适用技巧、关联知识”组织。未定阵开局与阵容专属运营分开；每个棋手×打法的前中后期强弱、战力条件及空窗风险由阵容分支同源生成，缺依据明确留缺。阵容运营按棋手等级补升级目标、找牌、停留及升级判断，具体规范见棋手分支。正式表达使用棋手升级、棋手等级，不使用借用的“本”字表达。

正式笔记以中文标题生成文件名，稳定 `id` 不变；以索引的 `path` 查找笔记，禁止用 `id + '.md'` 猜路径。首次升级运行 `wxq.py migrate`，同步迁移旧文件及关联链接；保留恢复副本。阵容同名 JSON 与 Markdown 均是索引的生成物，必须通过统一保存入口更新。

导入阵容时读取知识契约的 `meta`：必须阵营、适用棋手、核心英雄、前中后期英雄组成（必需/可选、作用、替换）、禁用阵营适用情况，以及明确目标的针对策略。禁用的是阵营，例如大河、三分、逐鹿、河洛、日落海。只填证据确认的内容，缺失保留待确认；不能把“未提到依赖”当作禁用后可玩。新阵营或未知英雄显式记录 `pending:中文名称`，不伪装官方实体。

网页可编辑正文和 meta。修改正文的章节列在 `manual_sections`，人工修改 meta 标记 `manual_meta=true`；人工结论 `origin=manual` 且不附视频证据，原结论与证据保留在 `history`。提交前必须读取人工修订：相同结论不产生重复；不同结论进入 `conflicts` 待核对，不自动覆盖人工内容或把旧来源当作修改后的依据。需要解决冲突时，核对新证据与人工意图，通过统一保存入口维护知识，再显式移除已解决冲突。棋手Markdown允许按固定格式直接编辑并同步读回；其他JSON生成物不得单独手改，不得通过重放旧导入绕过保护。

前端来源清单位于 `knowledge/source-registry.json`，技能默认登记与网页手动添加共用入口，登记仅代表待整理。处理时结合清单链接和备注，沿用既有 prepare/commit/finish 流程；关联笔记从证据及历史推导。每次成功或失败结束时，用 `workspace.sources` 核对本次各分 P 的阶段、错误、沉淀状态和关联笔记，不手工填写成功状态。`complete`、核对记录有效、已经提交关联知识三者齐备才显示已沉淀。

网页“爬取”支持B站关键词搜索及UP主每日/手动监听，经SQLite持久化队列调用同一prepare和large-v3转写，自动导出各分P文字稿。手动登记仍只登记，不自动处理。网页采集完成只代表文字稿已生成／待核对，不能自动commit或finish；后续仍逐段核对、关联扫描和提交。网页与CLI共用BV处理锁，避免同时写同一来源；自动登记使用 `register_source(..., preserve_annotations=True)` 原子保留人工标题/备注。文字稿存在时复用并保留人工修订，不强制重导出。

网页采集优先复用有效文字稿及完整转写产物；无现成转写时按实际分P检查B站字幕，优先人工中文字幕、其次自动中文，同类简体优先。字幕有效则直接导出待核对文字稿，跳过音视频下载、ASR和自动取帧。原始字幕、时间轴及来源分别保存为 `subtitle.raw.json`、`subtitle.corrected.json`、`subtitle-source.json`，不伪造ASR模型记录。文字稿索引的 `transcript_origin=bilibili_subtitle` 表示字幕来源；无可用中文字幕回退ASR。字幕登录/风控/网络失败需保留真实原因，刷新一次会话重试后可自动回退独立音频与large-v3，记录 `subtitle-fallback.json`，不得将请求失败记为无字幕。音频也受限时进入持久化等待；跨进程限速与会话恢复不阻塞本地ASR。人工文字稿不覆盖，字幕不能代替画面证据或自动完成知识核对；CLI仍按需取帧、核对及提交。

搜索扫描独立于下载转写，视频默认并行2个、可配置1–4个，不同批次公平派发。导出文字稿短暂等待共享写锁。删除网页任务会停止其独占处理，共用视频继续，已采集内容/文字稿和恢复素材保留，不等同删除知识来源。墓碑任务不能被后台迟到结果复活。

采集队列与日志位于 `raw/crawler/`，搜索及UP主元数据通过前端sources投影展示，不写入知识结论。网页转写成功、文字稿有效后清理临时音视频，保留ASR/元数据/纠错/关键帧；需要回放音视频时可重新获取。原始ASR未检测到语音时导出明确的无语音文字稿，不能据此生成结论。具体运行与接口见项目 `frontend/README.md`。

网页与 CLI 提交共享操作系统写锁；遇到占用稍后重试。启动时先重放 `pending-save.json` 恢复，再处理 `pending-commit.json`。`frontend/start.ps1` 构建并启动本机网页；默认仅 127.0.0.1。

## 通用策略筛选

每条内部结论必须标记 `kind`：`mechanic`（机制）、`general_strategy`（通用策略）、`conditional_strategy`（可复用的条件策略）、`match_action`（单局操作）。正式知识只接受前三类，单局操作保存到内部报告。通用不等于无条件；例如对手有范围伤害时分散图腾，可以保留明确条件下的策略。

逐条区分讲解中的规则与当局选择。混合段落先拆开，再分别处理。实战操作只有讲解明确给出可复用理由、适用条件清楚时才能入库；不能凭一次操作或获胜结果泛化。具体竞拍结果、当局装备优先级、等级转移目标和等待回合数，未经通用讲解支持不得保留。未确认简称、操作顺序与识别问题放内部报告。没有可靠通用内容的必要字段写“暂无已确认的通用策略”。

重新筛选旧知识时，保存移出内容、原证据及移出原因；替换索引与重放导入数据并更新关联链接。保留人工修改，核查依据，不根据旧导入覆盖手写修订。

## 官网卡牌知识、阵营依赖与全文存档

`sync-entities` 在保留 `entities/` 原始属性、来源和历史的同时生成 `knowledge/cards/index.json` 与分类中文 Markdown，供网页“卡牌库”查阅。卡牌效果、阵营、英雄品阶、普通／觉醒、技能、等级强化及基础属性按官网实际字段整理；单位按保存的官网展示代码转换。缺失字段明确未提供，不猜测；觉醒卡借用普通英雄技能时说明来源，不当作独立觉醒强化。卡牌资料与视频攻略结论分开维护，官网部分失败保留既有数据。

先依据攻略确定核心及关键输出、成长、控制和辅助成员，再查询其官网阵营。必须阵营从核心及中后期 `necessity=required` 成员推导；前期过渡、可选及无阵营英雄不纳入。关键辅助不因其不是主要输出而被排除。必须阵营被禁判完整推荐不可玩，说明缺失英雄与作用；有证据的替代路线另述，其他无证据条件保留待确认。此规则补充上文的meta要求，不根据全文提及或官网标签擅自确定必需英雄。

逐段核对已有完整文字稿及纠正版；仅在全文尚未导出或纠正版实际更新时执行 `wxq.py export-transcripts SOURCE_ID`，保护人工修订后再执行 `finish`。完整文字稿存项目根 `raw/BV编号_pN.md`，保留讲解与实战、原时序、时间戳和待核实项，不能用知识摘要替代。`raw/index.json` 记录原始、修正及输出摘要；人工修改不得覆盖，差异保存在 `raw/reports/transcript-conflicts/`。无参数 `export-transcripts` 补录全部已完成来源。确认漏识别时独立保存补转写记录后合入纠正版，不修改原始ASR；无法补核则标待核实，不伪造原话。官网新数值不替换旧视频数值。finish和validate要求有效文字稿及摘要。

## 输出给用户

默认采用“共通流程＋路线差异”的阅读组织，用户明确要求每条路线独立完整时再分别展开。英雄清单列成员、具体作用、逐阶段觉醒档位及原因、后期等级投入及替换条件；禁用条件单列，针对对手的威胁、换装和站位归入对局应对。每条有效结论有且仅有一个正文主要展示位置，运营路线及后期组合不再次全文展开引用结论。正文、meta摘要和重放输入同步具体名称；详见 [内容组织与HTML导出标准](references/editorial-standards.md)。

知识 Markdown 只展示可读攻略，不展示来源标签、内部版本标签、视频链接、时间戳引用、图片证据或统一免责声明。实际条件与行动同行展示；来源、ASR、纠错及图片保存在内部资料中。本地关联知识链接保留。真实版本冲突集中写在附录的“版本差异”中，影响操作的条件直接写进建议。

写作时明确“什么情况下，对哪个单位，做什么，为什么”。区分英雄品阶、英雄等级、棋手等级与人口；“D牌”首次解释为花金币刷新商店找英雄，“主C”可作角色标签，但实际建议明确具体英雄。避免“弱场”“吃来牌”“吸等级”等含糊表达，改写为具体局势、获得目标英雄的难度及明确的等级转移对象。核心原理、阶段运营和逐卡说明按v4单段要求组织，不把缺失信息补成确定规则。ASR缺口和误识别过程留在内部报告，正文仅保留影响操作的待核实项。

仅优化已有措辞时，保留结论的内部证据、版本、条件及关联关系，在索引中替换文本并同步维护导入数据；不要通过普通增量合并追加一份改写结论。使用原子写入及恢复副本，再重新生成 Markdown。

给出本次新增/更新的知识文件链接、各类实体同步数量、主要纠错和仍需核实的问题。链接失败、识别失败、官网缺失类别要明确说明。测试没有获得真实音视频时，不能生成虚构攻略或声称 ASR 测试通过。

修改或验收本技能时读取 [references/acceptance.md](references/acceptance.md)，运行单元测试、skill-creator格式校验、`wxq.py validate`，并区分模拟测试与真实视频结果。


## 灵活阵容知识

整理或补充阵容时，按[主要变阵规范](references/major-variants.md)检查完整打法分支，并维护“主要变阵”章节与`meta.major_variants`。核心不变但成长／运营体系实质改变也可成立；挂件替换、单纯棋手升级快慢、决赛圈临时太乙真人／钟馗不单列。无可靠依据允许为空，网站相似组合不直接充当攻略证据。有棋手分支的新写入使用schema5；旧schema4和schema3继续兼容读取。

导入同一棋手的通用打法时，保持 type=lineup、知识字段和章节归属的语义；阅读版依照版本3表达及版本2语义目录组织，不强制逐字段重复展示。根据视频证据在 meta.operation_routes 保存各运营节奏的条件、优势、风险、转向条件及阶段结论引用，在 meta.late_variants 保存全部已确认推荐的后期组合。有棋手分支的新写入使用 schema_version=5 契约（兼容旧版读取），不将不同组合的成员拼成一套固定阵容。只在来源明确支持时建立节奏与组合适配关系。全局依赖与组合依赖分别维护，多个阵营同时被禁的可玩情况需要联合证据。

融合时先区分条件与真实版本差异，无法解释的冲突列出双方结论、来源时间段和操作影响，请用户裁决；未裁决前不得写成确定推荐。正文沿用来源隐藏规则，完整证据保留在 claims 和 raw 内部报告。
