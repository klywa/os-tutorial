# 解释优先级与反馈复盘

## 从正式库读取

在项目根目录执行以下只读查询。通过组 ID 或话术 ID 回到原记录，跨批次保持同一身份。线上批注复盘使用对应站点内已获授权的反馈记录，区分数据来源。

```powershell
.wxq-runtime/Scripts/python.exe -X utf8 .codex/skills/wanxiangqi-template/scripts/read_feedback.py comments --status open
.wxq-runtime/Scripts/python.exe -X utf8 .codex/skills/wanxiangqi-template/scripts/read_feedback.py history --latest
.wxq-runtime/Scripts/python.exe -X utf8 .codex/skills/wanxiangqi-template/scripts/read_feedback.py history --group-id 稳定组ID
```

## 怎样使用反馈

- 保留用户纠正的原意，定位到正式组 ID、话术 ID、触发动作和当时版本。整组意见与某一句的意见分别记录。聊天指示可直接使用；其涉及的机制应与正文、官方卡面或原始证据核对。
- 查看相关的正式批注、回应和最近管理员操作。批注记录提出的问题，改稿前后差异说明修改了什么。原样采纳说明认可了当次内容；仅凭采纳、删除或关闭批注，不能推断管理员为何这样做。批量批准中的每组按自己实际获准的差异理解。
- 将同因反馈合并在下方对应判断中。新反馈若改变适用边界，修订原有判断，并在正式历史中保留来源。人工确认的改句只收进对应事件的案例库。版本原文留在反馈记录中；本页维护影响生成选择的标准。
- 用这条判断复核同篇的其他实体、同一动作在不同阶段的模板及可能抢先命中的通用组。至少用一个原反馈没有点名的对象检验能否迁移。交付时说明哪些候选随之修改、哪些可保留及原因。有据的策略结论按知识技能和本批授权写回相应笔记。

## 按什么决定先讲哪件事

- 从阵容在该阶段要做的事倒推英雄的职责。单挂解释为什么一个人也能过渡，补四人组解释补进了哪类战斗力，针对位解释它如何影响这个对手。卡面机制应能解释这项职责。以全部同类角色为复核范围，覆盖买、上、合成等动作各自兑现的收益。
- 「如果还没觉醒」「想继续升级时」等开头提示作者检查条件。先判断觉醒、资源、紧迫程度或配合是否已有可用字段。能可靠判断就写进条件并直接说收益，含随机性的结果保留不确定措辞。
- 对行动时点、阶段职责、作用目标和资源逐项找反例。中间效果若只是通往目标的一步，讲清最能解释此刻取舍的最终收益。可观察的必要状态放进条件；涉及概率或后续操作时保留不确定性。
- 沿资源与受益者两端分别检查取得途径。比较换用另一对象后是否仍有独立教学价值，并核对范围、次数和目标选择方式。推荐阵容时每条候选句的路线均须对应事件参数。
